Test history, for transparency: a first version framed the fact as a secret "vault access code", and the model declined to repeat it, so it was changed to a harmless release build tag. That version then scored 11 of 12: its one miss was at 64K, where the code excerpt ended mid-file and the model read the question as part of the code ("no actual task or question was included"). The final run above adds an explicit end-of-files marker before the question.

Finding: a narrow miss just past 64K

Both misses were in the 64K case, so it was probed further with a fact at 90% depth. Prompts of 63K, 65.5K and 70K tokens answered every time, but prompts of about 65,620 tokens missed in 5 of 7 tries: the model describes the code and says no question was asked, as if it does not see the question at the very end. 96K and 124K are unaffected. This looks like an edge case in the serving stack at that length (prompts are processed in 2,048-token chunks, and the last chunk there is only about 84 tokens), not a general long-context limit. A normal coding run

Multi-turn tool use with real test execution

An agent-style session: system prompt, three tools (write a file, read a file, run the tests) and a task to build a small Python package with unit tests. How it was measured

  • All requests went straight to vLLM's OpenAI API on the B70 (no proxy), streamed, with token usage returned at the end.
  • First token is the first streamed token of any kind, including the model's reasoning. First answer is the first token of the visible reply.
  • Prefill = uncached prompt tokens / time to first token. Decode = (output tokens - 1) / (end - first token), thinking tokens included.
  • DSpark figures are deltas of vLLM's spec_decode counters around each request. Kept = accepted / drafted; tokens per step = 1 + accepted / drafts.
  • Energy is the card's own energy counter (hwmon, whole board) over each request, so it includes idle power while the request runs.
  • Every prompt size was run once before measuring, so first-use kernel compilation does not appear in the results. Long prompts carry a unique first line, so cold runs never hit the prefix cache.
  • Sampling: temperature 0.6 (0.3 for the coding run), top-p 0.95. Output varies a little run to run, as with any sampled model.
  • vLLM's request counter was read around every phase and matched the harness exactly (bursts 24, long context 20, recall 12, coding 8, concurrency 19), so no other traffic reached the model during the measurements.
  • Concurrency was measured with the server allowing 8 requests at once (--max-num-seqs 8), after one unmeasured pass of the same tests; every other test ran with 1.
